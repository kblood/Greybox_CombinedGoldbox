- `dos_files.rs`: `find_exact` supports exact names, flags 0/10h; files live in a BTreeMap. That container order is not evidence of DOS enumeration order. Store metadata has size, attributes and basename, but no timestamps.
- `startup_platform.rs`: AH4E routes to `find_exact`, then builds a 43-byte DTA. `write_dta` preflights the entire destination through the existing guest memory guard before writes. `save_result` changes AX/CF. AH1A records the active segment:offset. AH4F is absent.
- Existing DTA bytes +15 attribute, +1A..1D size and +1E..2A filename are populated; reserved bytes and time/date are zero. Do not silently describe these synthetic timestamp fields as original metadata.

The Microsoft MS-DOS Encyclopedia specifies CF clear on search success, CF set with error AX on failure; AH4F without prior search or after exhaustion returns 12h. Its DTA reserves the first 21 bytes for continuation, with filename at +1E; preserving this search information permits subsequent calls. AH4E errors include 2, 3 and 18. Success AX is not specified. These facts do not establish this mounted DOSBox drive's ordering or all mutation behavior. ## Narrow implementation contract, after oracle review

1. Add a separate search-path parser: split only final component, accept case-insensitive literal `*.WHO`, canonicalize its parent with existing CFG/CWD rules, and require equality with the configured save directory. No recursive scan, wildcard directory, `?`, other suffix, traversal, other drive namespace, assets search or host filesystem enumeration. Preserve all existing exact AH4E behavior. Attribute zero only for this new pattern; unsupported forms fail explicitly.
2. Enumerate direct regular save-store children with representable DOS 8.3 names and WHO extension. Never silently truncate a long basename, include a subdirectory, or expose host files outside the completed import. State the treatment of an unrepresentable matching imported name as a guard failure, not a fabricated alias. Missing directory versus empty directory must follow the oracle result below.
3. Keep bounded continuation metadata on the host, using a generation/token in the reserved DTA region. Lookup is not solely a global cursor or filename: AH1A switching must resume each search independently; Pascal rewriting +1E must not invalidate it. Preserve legitimate copied-DTA continuation if confirmed by the oracle; a token copied with its continuation position can identify the same immutable search independently. Prefer one shared immutable name sequence per supported configured-directory/pattern/store generation, with each cursor encoded in its DTA token. Proposed bounds are 4096 aggregate names and 256 KiB aggregate name storage, checked before collection. Cap exhaustion is a truthful resource failure, never silent partial results or ordinary no-match. Replacing a search at one DTA must NOT release a sequence still referenced by an unknown copied DTA: guest RAM copies cannot be reference-counted by the host. A shared current-generation sequence avoids per-DTA lifetime counting and the proposed arbitrary 64-search lifetime limit. Generation, cursor bounds and supported pattern must be validated before continuation. Finalize this representation only after copied/interleaved-DTA oracle evidence; it is not a claim about DOS's reserved byte encoding.
4. Prepare result, next continuation and DTA bytes without changing live search state. Preflight all 43 destination bytes and reserved-token reads. Only after successful guest commit advance/install the cursor. Invalid segment range, protected memory or guest service rejection preserves DTA, cursor, handles, files and registers; propagate the existing machine guard status. Ordinary DOS errors update only the documented result registers/flags through the existing path. Preserve other flags and registers; do not depend on unspecified success AX in original wrappers.
5. Exhausted or unknown continuation returns DOS18, without pretending a match. Preserve the prior DTA on unsuccessful search unless oracle evidence requires otherwise. AH1A itself selects a pointer; do not newly force a DTA write at pointer selection. Initial no-match/replacement failure behavior needs the oracle before implementation is frozen.
6. Enumeration order and mutation policy are release gates, not implementation guesses. Use the pinned oracle's observed order for the tested mounted-drive profile; do not claim universal FAT ordering. Proposed bounded policy is an immutable name sequence per search, current metadata checked at delivery, and explicit invalidation on relevant successful store mutation if compatibility cannot be established. That invalidation is a declared unsupported case, not DOS18 or stale success. Failed mutations must not invalidate searches. Creation/deletion/resize between calls and DTA copying need explicit evidence before choosing the final policy. The original observed Add list performs reads, so mutation support is not prerequisite to its first cold route.

**Cursor correction:** case8 row27 starts A.WHO in DTA0; row29 uses the copied DTA1 and gets B.WHO; row31 resumes DTA0 and gets EOF. Copies share a host cursor. It is NOT an independent position copied in DTA bytes. Case6 separately started searches remain independent. Consequently use a unique search-context token per FindFirst, shared mutable next-position in the host context, and token copies alias that context. Never share the cursor merely because pattern/directory match, and never store authoritative position in DTA. Original filename conversion changes +1E only and leaves the token usable (case7).

Implementation rules:

1. Retain the original narrow path/attribute gate: only final `*.WHO` in configured mutable save directory with CX0. Existing archive-only imported store is the supported metadata profile. No host traversal, arbitrary wildcard, hidden/system/read-only emulation or attribute-setting service is added. Case14 includes those files despite CX0 and excludes directory; document the observed result rather than override it with manual assumptions. Current store cannot represent those distinct attributes, so this does not authorize inventing them.
2. Snapshot matching direct-child names in ascending canonical ASCII order for this measured profile (case4 A,B despite B-before-A creation). Size/attribute values come from actual store metadata; no synthesized WHO contents. Missing parent returns3; existing empty returns18; exhaustion and never-started FindNext return18. Success observed AX0/CFclear; preserve unrelated registers/flags and existing AH1A pointer/flag behavior. Exact legacy searches remain unchanged except that a successful/failed new FindFirst must not leave the old active wildcard token accidentally resumable at the selected DTA.
3. Use unique monotonic nonwrapping context tokens in reserved DTA bytes, bounded to64 retained live contexts and4096 names/256KiB aggregate storage before allocation. These are explicit resource limits, not DOS search semantics; cap failure is truthful resource failure, never EOF or partial success. Replacing one DTA must not free an unexhausted context that an unknown copy may reference. Exhaustion can release its name storage; its expired token resolves EOF, and tokens are never reused. Repeated abandoned searches can reach the bounded resource limit; do not introduce LRU eviction or guessed reference counts. Cold Add's ordinary complete enumeration is not such a leak. Track token overflow explicitly.
4. Failed supported FindFirst replaces the selected DTA's continuation with an exhausted/invalid-search token while preserving result metadata/name. Case10 row36 changes reserved bytes, leaves previous A.WHO metadata/name intact, and row37 returnsEOF. Missing-parent row2 also changes reserved bytes. Thus the earlier proposal to leave the entire DTA unchanged on ordinary FindFirst failure is withdrawn. Invalid guest memory/unsupported request/resource preflight failures remain atomic guard failures: no DTA, context, cursor or result-register partial commit. Distinguish these from a valid DOS no-match outcome.
5. Read/preflight the complete43-byte DTA before building a candidate update. Write only owned token bytes and documented result fields; preserve remaining reserved bytes and bytes after the filename's terminating NUL. Actual successful shorter names retain tail bytes (A.WHO after KRA.WHO), and FindNext error leaves the entire DTA unchanged. Existing synthetic zero timestamp policy must be explicitly retained as a limitation, not represented as recovered timestamps. No raw private DOSBox token-byte equivalence is claimed. After successful preflight and memory commit, install/advance host context; no failed write advances it. Tests assert untouched sentinels and exact preserved bytes, including original Pascal overwrite.
6. Preserve observed mutation cases without claiming more: creation of a new matching name after FindFirst does not extend the snapshot (case11); deletion or resize of the already returned A leaves pending B available (cases12/13). Failed store mutations change no search state. Mutation of an as-yet-unreturned candidate is unmeasured: mark the affected live context unsupported and reject continuation truthfully through the existing unsupported boundary, rather than deliver stale metadata/file or return ordinaryEOF. Do not invalidate all contexts on any generation change, since that would contradict cases11–13. An identical-name replacement/truncation of a pending candidate is included in this unsupported policy. No additional oracle breadth is necessary for first cold Add, whose list reads do not perform these mutations.
