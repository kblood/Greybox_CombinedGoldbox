Set 2026-11-09 by the user. The long-term aim is a full Champions of Krynn implementation. The first
milestone is a complete graphics versions comparison overview, because the rest of the graphics
research and browser work depends on it.

## Standing loop rules

An autonomous loop continues this work across sessions. Each tick must:

1. Read this file, the [graphics data README](../data/graphics/README.md) and the newest handoff
   notes. Do not rely on memory alone.
2. Pick the highest-priority open task whose exit criteria are not yet met. Prefer tasks that unlock
   the milestone over annotation volume.
3. Do the work, verify it (tests, typecheck, reproducible checks), and record results in a dated
   research note.
4. Generate follow-up tasks for anything discovered, and add them to the task list below.
5. Stop and report, rather than guess, when a task needs a decision only the user can make, or
   touches a hold: builds, browser acceptance, runtime execution, deployment, pushes, or anything
   hard to reverse.

Git: the user has asked for commits and pushes to origin master, each with the Co-Authored-By trailer.
Deployment is authorized by the user (2026-11-09) once a user-visible change is verified and the build passes
the public-artifact audit.

## Milestone 1: complete graphics versions comparison overview

Exit criteria:

- Every CoK registry source appears exactly once in an overview with its platform, edition, archive,
  counterparts, restyle records and explicit gaps. Verified by test against the real registry.
- Pixel-identity relations are shown as recorded relationships. Counterparts are never merged into
  one identity, and no shared subject or game use is asserted from pixels.
- The browser has a usable overview page: filter by platform, edition, status and archive; page
  through rows; open any source in the existing asset panel.
- Coverage numbers are reported per archive and per platform, with unrecorded platforms labelled as
  unrecorded, not absent.
- Build, browser acceptance and deployment remain on hold until the user lifts them.
