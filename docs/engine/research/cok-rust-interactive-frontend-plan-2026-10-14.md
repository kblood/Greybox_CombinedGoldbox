## Increment B: window, presentation and keyboard

Connect the existing Windows C shim and Rust framebuffer/window foundations. Compile the shim through the existing toolchain and link `user32`/`gdi32`; no new UI dependency is required. Check the C/Rust key-event ABI explicitly.

Present the actual EGA planes through side-effect-free peeks. The initial presentation profile is mode 0Dh, page zero, 320 by 200 pixels, with the declared fixed EGA16 palette. Presentation must preserve EGA latches and guest state. Unsupported startup display modes show a presentation status while source execution continues. Resize and repaint do not charge source work.

Keyboard events enter the BIOS data-area ring through a checked, atomic enqueue operation. Validate bounds, head/tail alignment and free capacity before committing the word and new tail. Record accepted and rejected input, ordering and source-work boundaries. The initial profile accepts declared basic US keys; it is not a claim of full BIOS keyboard compatibility.

An empty blocking input read needs a narrowly guarded cooperative wait. For interactive execution only, recognize an **already admitted direct CD16/AH0 site**, validate its source bytes, module and generation, and validate the ring **before IRQ admission or instruction work charging**. Waiting preserves IP, FLAGS, clocks and frames. After enqueue, execute and charge that instruction once. Do not clear fault 28 or replay an already charged service. AH1 and legacy headless behavior remain unchanged.

Use finite work limits because retained diagnostics are not suitable for unlimited sessions. Leave the final frame and source boundary visible after execution stops. Preserve Alt+F4 and orderly closure. Automated testing uses window-targeted input and capture; it must not activate windows or inject global input. Original DOSBox automation, if needed, uses GameLink.

Added-text ceilings after increment A: frontend glue 7 KB; enqueue/wait guards and declarations 4 KB; build/main/layout glue 1 KB. The complete `frontend.rs` stays within 12 KB. Astra approved the revised glue ceiling after source review: the additional text supplies bounded observations, input receipts, deterministic schedules and window-local controls needed to verify actual execution. Admit no new original instructions in this increment.

The initial input policy records rejected events without retrying them, including a transient rejection during protected REP execution. This is a declared limitation of the basic input profile. Input-head and execution-status transitions request bounded observation records so consumption, waits and stops remain inspectable.
