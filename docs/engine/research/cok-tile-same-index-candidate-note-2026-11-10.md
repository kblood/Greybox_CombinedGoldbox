# Tile candidates by same tile index — 2026-11-10

Goal file: [cok-full-implementation-goal-2026-11-09.md](cok-full-implementation-goal-2026-11-09.md).
Method gap: [cok-tile-candidate-method-gap-2026-11-10.md](cok-tile-candidate-method-gap-2026-11-10.md) (option b chosen).
Candidate list: `cok-tile-same-index-candidates-2026-11-10.json` (generated by a temp script from the gap queue).

## Decision

The user chose option (b) on 2026-11-10: a tile gap row is a candidate only for the location peer with the same
`tileIndex` in the same block. This is a new candidate rule, recorded here as the method decision. It adds no
threshold and no edge.

## Result

| Measure | Value |
| --- | --- |
| Tile gap rows with a same-index peer | 134 (Amiga 54 rows, DOS-EGA 80 rows) |
| Candidate pairs (was 8,292 under the old per-block rule) | 166 |
| Whole-image rows (no `tileIndex`) | 17, not covered by the rule |

Candidate pairs are unreviewed. Every candidate has `outcome: null` in the JSON.

## Not decided

- **17 whole-image rows** (all `cok/dos-ega/disk2/8x8d2.dax/block/*/whole`) have no tile index, so the rule does not
  reach them. They stay as recorded absences until the user chooses a rule for them (for example: leave them, or
  pair by whole-block number, which would be a second rule).
- The rule relies on the tile numbering being comparable between Amiga and DOS. That is an assumption of the
  user's choice, not something checked here. The first visual batch will test it. If same-index pairs turn out to be
  unrelated across the board, the rule fails and the note will say so.

## Not changed

- No edge was added and no status changed. No pixel-identical link was added (0 exact matches were found earlier).
- The native-size gap and the scaling default are unchanged.
