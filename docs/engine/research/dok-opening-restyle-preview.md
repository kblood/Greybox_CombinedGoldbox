This is **one picture in a playable ECL dialogue**, not a complete DoK graphics mode or an assertion that all same-numbered DOS/Amiga frames match. `apps/web/src/ui/explore.ts::startDokRetailCampaign` decodes the selected DOS `BIGPIC1.DAX` and `PIC5.DAX` for its retail opening. The actual opening `ECL1.DAX` block 16 emits `PICTURE 113` after picture 96; the focused `apps/web/test/dok-restyle-preview.mjs` advances the running ECL dialogue to 113 and observes the displayed pixels without changing dialogue text or advancing the scene during a graphics switch.

- Gallery comparison `scene_dok_skeleton_dragon`'s 1216×480 original is **pixel-identical** to a nearest-neighbour 4× enlargement of decoded DOS `Death Knights of Krynn/BIGPIC1.DAX` block 113, native 304×120 at (0,0). This was checked by comparing all RGB pixels (Pillow `ImageChops.difference(...).getbbox() is None`), **not** by trusting a shared block number.
- WHDLoad `DeathKnightsOfKrynn/data/BIGPIC1.DAA` block 113 independently decodes to a 304×120 Amiga image of the same skeletal rider and dragon composition. Reviewed source archive SHA-256: `29451e8561ed16a6dabc4560c890e02d8bb2cc77c320691119c29dad541c3b23`. This is a scene-identity check, **not** a claim of pixel equality or automatic compatibility with other Amiga installations.
- The reviewed Restyle output `004_scene_dok_skeleton_dragon.png` is 1824×720 (6× native), SHA-256 `baf59cd1707307c2793b763395de5eca8666e5056c6174ec374d3daddb9fb6a5`. Its gallery fidelity result is `ok`, which alone was **not** used as identity proof or an automatic review/approval of other outputs. The preview authorizes only this exact hash. The PNG is an existing ignored gallery asset, not a game file added to Git; a missing or changed output fails closed to original art.

The scene control says `preview only`. DOS-EGA always appears; Amiga is offered **only** if the exact reviewed `BIGPIC1.DAA` archive is readable from the selected installation's asset source, its digest matches, and frame 113 has the checked dimensions. It never borrows a separately installed Amiga game for a DOS-only selection. For this reviewed scene, Restyle and Amiga use native-positioned full-colour RGBA compositing (8,8) over the DOS HUD without recolouring its palette; all other DoK pictures retain existing original rendering. The pure resolver's DoK fallback order is Amiga, then DOS **when an Amiga source is actually loaded**. No C64, Atari, Apple or unreviewed art is advertised by this control.

The scoped engine catalog in `packages/engine/src/graphics/installationArtCatalog.ts` can filter explicitly selected installation IDs, but this web pilot does not yet bind the Library selection to that catalog. Full-game art dispatch, arbitrary-installation original matching, persistent game-wide selection and all-system coverage remain open. The CoK PIC1#58 fidelity flag remains excluded.
