# Explicit installation scope for reviewed art

`packages/engine/src/graphics/installationArtCatalog.ts` adds an in-memory, engine-neutral boundary *before* `createArtModeResolver`; it does not change that resolver's API. A host provides reviewed `InstallationArtRecord<T>` values: stable opaque installation `sourceId`, declared `game` and `system`, exact `(game, logicalId, optional frame)` identity, provenance locator, and an optional already-loaded asset. The active session provides `game`, ordered per-game `GameArtPolicy` values, and **explicit** `allowedSourceIds`. Example: for CoK, select only `user-cok-dos`, or explicitly select both `user-cok-dos` and `user-cok-amiga`. A source ID cannot stand for two games or systems; matching filenames/block numbers do not create identity mappings.

`createScopedArtCatalog` validates *all* supplied record metadata and policy relations, rejects duplicate records, duplicate/unknown allowed IDs, foreign-game authorization and ambiguous selected `(game, logicalId, frame, system)` records from distinct installations. It ignores **unselected** records for resolution (including loaded Amiga bytes), allowing multiple same-system installations to coexist until explicitly selected together for the same frame, at which point it rejects the ambiguity rather than guessing. Allowed IDs must occur in at least one record. The scoped resolver registers only the active game and selected originals; queries for other games throw. `sourceFor(ref, system)` identifies the selected installation behind an exact mapped original even when its pixels are not yet loaded. An absent source mapping reports unmapped/unloaded in `availability`, while an authorized but unloaded mapping reports mapped/unloaded. Fallback tries only selected loaded originals, in the active game's priority order; an original-mode request starts with the requested system. System names not mapped/loaded do **not** imply a selectable drawable mode.

Restyle candidates for other games are excluded from this scope. For this game's candidates the existing resolver still requires **approved and loaded** output; pending/rejected or missing outputs fall back to the best *authorized* original, then honestly report missing if none exists. No approved candidate is inferred from a gallery result. C64, Atari ST, Apple II and future system labels are ordinary explicitly prioritized strings, not automatically enabled platform support. The synthetic tests cover only this contract, not real port coverage or asset correctness.

**Host obligation:** a stable ID and an `asset` are claims supplied by the caller. The shell must authenticate the user's choice, bind every ID to a canonical immutable installation, verify game/platform/locator and loaded bytes, prevent path escape and avoid loading unauthorized bytes before constructing this scope. Rebuild the catalog when permissions or installations change; do not reuse a resolver from an older session after revocation. This pure helper neither reads files nor proves ownership, bytes, review fidelity, or UI integration. The existing CoK picture-112 web pilot remains single-source; no web or native path is wired to this catalog yet.
