## Historical draft GSK1 / GBKO model

At the draft checkpoint, `tools/secret_continuation.py` was a pure reference
model without filesystem mutation or native runtime wiring. That historical
draft had not shipped as an ABI; current GSK2 integration is described above.

GSK1 has a 64-byte little-endian header (`<4s10H10I`): magic, version1,
phase, title4, profile1, party count, original area, header length64, interactive
mode0/1, resume kind0=combat/1=menu/2=empty, one zero reservation, then ten u32
section lengths. Ten 112-byte
canonical DOS paths follow: source, roster, request, result, paused effect,
seed, outcome, successor, authority and working directory. Sections are exact
request, roster, paused effect, seed, identity, result, outcome, successor,
stream and producer receipt bytes. Total extent must match exactly.

Prepared owns full inputs. Completed additionally freezes an unconsumed result
and its exact matching outcome. Active additionally owns the validated successor
and a GBKO producer receipt. The logical HP-settled substate is inferred only
from the exact consumed result plus complete projected post-roster, preserving
HP-only changes and all other roster bytes.

GBKO's 24-byte header (`<4sHH4I`) contains magic, version1, header length,
completed-input length, successor length, stream length and a zero reservation.
It embeds the complete encoded input record and exact successor. The intended
native wrapper must mint it after successful output close/validation, then
publish authority atomically. This reference function is not evidence that a
native wrapper executed or a filesystem publication occurred.
