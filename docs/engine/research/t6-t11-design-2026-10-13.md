Scope: `round10-task-list-2026-10-07.md` T6 (DOS first-person encounter art) and T11 (FRUA

## 0. Findings that change the task list

1. **The byte budget in the task list is not the manifest's.** `native/build/native-capacity.json`
   (read-only; `native_source_sha256` 32023cab...; built from a tree that may differ from the dirty
   one) says: GBBOOT 64,575 emitted / 64,831 resident / **449 free**, floor 128, so **321 usable**;
   CCFP 24,840 / 61,494 / **3,786 free**, no floor. The task list quotes "8,501 usable" for GBBOOT
   and "6,402" for CCFP. T4 (-80..150) + T6 (-60..120) + T11 (-200..400) = 340..670 against 321
   usable. **Either the 8,501 figure is from a different accounting or T11 cannot land in GBBOOT
   without an extraction.** Not resolved; whoever owns `gbboot.asm` must rebuild
   (`pwsh -NoProfile -File native/build.ps1 -Target engine`) on a clean tree before T4/T6/T11 are
   scheduled. I did not rebuild (forbidden here).
2. **T6 as written misses a second CCFP gate.** The task only lists `draw_effect_setup`. But
   `load_gbim` (ccfp.asm, ~3606) sets `gbim_enabled` only when `graphics_alt_enabled` is set or
   `scene_overlay` is set, otherwise falls to `.bad` with `gbim_valid=1, gbim_enabled=0`. Under
   `/G 1` neither holds, so even with GBBOOT producing and passing `/I`, `draw_effect_setup` would
   still draw the marker. Both gates must change.
3. **Real CPIC data fits the existing GBIM contract.** Decoded `CPIC1.DAX` TOCs with
   `tools/dax_decode.py`: CoK 52 blocks (ids 1..187), DoK 106 blocks (ids 0..225); **every block's
   frame 0 is a standard frame** (height and width/8 both non-zero), so CGB's `.complex`
   ("unsupported") branch never fires. Sizes: CoK 24x24 x38, 24x48 x6, 48x24 x8; DoK 24x24 x58,
   24x25 x4, 24x48 x10, 40x24 x1, 48x24 x21, 48x48 x12. All are under CCFP's 160x160 GBIM bound.
   CGB decodes **frame 0 only**; no animation.
4. **Colour 0 is transparent in `draw_gbim`.** On EGA that is black, so black pixels inside a
   monster icon will be see-through. This is the existing Amiga behaviour and T6's acceptance
   bar already says so; it is a fidelity limit, not a bug to fix in T6.
5. **All 26 uppercase GBBOOT switch letters are taken** (A..Z, plus `@`, `?`, digits, parsed at
   gbboot.asm ~360-420). T11's "a design argument" cannot be a new `/x` switch; see section T11.

## T6, re-derived

### Where the marker is drawn
- `draw_effect_setup` (ccfp.asm ~3317), called from `render_view`'s `.world` arm (~1075) after
  `plan_wall_view`. Requires `effect_setup_valid` (v7 `GBES` tail). It draws a GBIM via
  `draw_gbim` only if `graphics_alt_enabled`, `gbim_enabled`, `gbim_valid` are all set and
  `effect_setup_pic == gbim_block`; otherwise `.marker` fills a colour-12 rect, width
  `max(8,28-4*dist)`, height `w+8`, centred x=92, bottom y=`132-12*dist`.
- Documented as a placeholder: `native/README.md` ~3120 and ~4728 ("until native CPIC/sprite
  encounter art exists"), and ~4835 ("missing, malformed, and nonmatching images retain the DOS
  encounter marker").
- `draw_gbim` (~3420): scale 2 when `effect_setup_distance <= 1` else 1; dest x = `92 - w*scale/2`,
  y = `132 - h*scale` (bottom anchored); colour 0 skipped. For a 24x24 icon: near (48x48) at
  (68,84); far (24x24) at (80,108).

### What already exists on the GBBOOT side
- `prepare_alt_graphics` (gbboot.asm ~8942). The Amiga branch (`.not_c64`: requires
  `graphics_requested==2`, `graphics_amiga_available`, `texflag`) execs `CCDAA` twice for the wall
  banks, then `.image`: `read_effect_setup_pic` (reads the 12-byte GBES at `GBEF_SETUP_OFF` into
  `fxbuf`, validates `GB`/`ES`, stores `graphics_setup_pic`, range 1..255), `find_amiga_cpic`,
  CCDAA `/B id /I altimagepath`, sets `graphics_image_ready`. **All three early-outs to `.scene`
  (`/G` not 2, no Amiga, no texflag) bypass `.image`**, which is exactly the DOS-player gap.
- `find_dos_cpic` (~9255) probes root, `DISK2`, `GAME` for `CPIC1.DAX` and sets `graphics_cpicp`.
  It is already used by `prepare_combat_graphics` (~10257, `.try_dos`, `eng_dax_gen1` only) with
  the CGB tail order `/B id /I out FILE.DAX`, `runpathp = child_gb`. A missing block exits CGB with
  errorlevel 1, so `do_exec_checked` carries CF and the group is skipped.
- The `/I altimagepath` argument is appended to the CCFP tail at `.maybe_image` (~9813) when
  `graphics_image_ready` is set. `prepare_alt_graphics` is called twice per step (~4309 and ~4364),
  so a DOS branch costs one extra CGB exec per call, as the Amiga branch does.
- `graphics_image_ready` is cleared only at `run_native_preview` (~3887) and
  `prepare_combat_graphics`. A stale `altimagepath` therefore cannot be mistaken for a fresh one
  only because CCFP compares `gbim_block` with `effect_setup_pic`; that id check is the
  provenance control and must stay.

### Minimal first slice (3 edits, 2 files)
A. ccfp.asm `load_gbim`: enable when the file validates, regardless of `graphics_alt_enabled`
   (drop the `cmp graphics_alt_enabled / cmp scene_overlay / je .bad` pair; `-8..-12` bytes).
B. ccfp.asm `draw_effect_setup`: drop the `graphics_alt_enabled` test (`-5` bytes). Keep
   `gbim_enabled`, `gbim_valid` and the `effect_setup_pic == gbim_block` match.
C. gbboot.asm `prepare_alt_graphics`: redirect the three early-outs to a new `.dos_image` label that
   requires `enginep==eng_dax_gen1` and `texflag`, then `read_effect_setup_pic`, `find_dos_cpic`,
   builds `/B id /I altimagepath` + ` ` + `graphics_cpicp`, `child_gb`, sets `graphics_image_ready`.
   Order matters: `find_dos_cpic` and `read_effect_setup_pic` both use `fxbuf`, so call
   `read_effect_setup_pic` first and consume `graphics_setup_pic` (not `fxbuf`) afterwards.
   Estimate 60-110 bytes, from the task list; I did not assemble it.

Palette: CGB writes the fixed EGA-16 palette into the GBIM's first 16 entries.
`apply_gbim_palette` is gated on `graphics_alt_enabled` and so stays off under `/G 1`, leaving the
DOS wall palette. That the DOS wall palette equals CGB's EGA-16 table in indices 0..15 is
**not verified**; it is a pixel-equality assumption the DOSBox test must prove.

Side effects to specify, not discover:
- `G` under `/G 1`: `toggle_graphics` `.enable` sets `graphics_alt_enabled=1` and
  `gbim_enabled=1` with empty bank names, so `G` will toggle the DOS icon off/on and flip the flag.
  Decide: accept ("G toggles encounter art in DOS too") or leave it. Either way the test must pin it.
- `step_sound` is skipped while `gbim_valid` (DQK walk sound). DQK is `eng_hlib`, so unaffected;
  README must say so.
- Gen1 titles other than CoK/DoK: whether their `CPIC1.DAX` shares logical ids with `GBES.pic` is
  **unverified**; the branch gates on `eng_dax_gen1`, not on CoK/DoK. The test should cover CoK and
  DoK only and the doc should claim only those.
- Command tail: CCFP's DOS tail has a 127-byte ceiling (see the long comments at gbboot ~10165);
  adding ` /I <altimagepath>` costs `4 + len(path)`. The Amiga path already pays it, but
  measure the longest `/G 1` CCFP tail in the existing flow routes before claiming it fits.

## T11, re-derived

### What exists
- GBBOOT FRUA detection (gbboot.asm ~1630-1667): `CKIT.EXE` + root `SCRIPT.GLB`, or
  `.check_frua_disk3` (`DISK3\GEO.GLB`). Both only `set_profile` with `game_frua`, `eng_hlib`,
  `note_frua`; the DISK3 case does not set `geop`. `.hlib_try_frua_script` (~1910) needs `geop` and
  root `SCRIPT.GLB`, else `.missing` zeroes everything: that is the fail-closed outcome.
- CCGEO already normalizes a direct design map: `open_frua_geo` (ccgeo.asm ~601, flag `frua`
  ~1999, `frua_len`) accepts one complete FORM/AMOD record; grid is 576 six-byte records at 322
  `{N,E,S,W,event,backdrop+zone}`. Documented invocation (README ~1058):
  `CCGEO /B HEIRS.DSN\GEO005.DAT 0 C:\FRUA.WGR`. Its test is `native/ccgeo-bridge-test.ps1`
  (~229-341), which uses a **synthetic** FORM/AMOD (3x2 map), not retail HEIRS. The task list's
  "HEIRS GEO005.DAT byte check" is therefore not in that script; I found it nowhere in `native/*.ps1`
  and did not trace it further.

### FRUA design data, read from the GOG install (`...\Unlimited Adventures`)
- Designs sit beside `CKIT.EXE`: `HEIRS.DSN\` (GAME001.DAT 388 B, GEO001..040 with gaps, 26 files,
  each **12,962 B**, `FORM` ... `AMOD`, STRG001/003, MONST1xx, SAVE\) and `TUTORIAL.DSN\`.
- Start module is **`GAME001.DAT` byte 48, entry byte 49, equipment byte 50**
  (`hackdocs_extracted/GAMEDAT.TXT`; `tools/frua_events.py` `parse_game` reads the same). Measured:
  HEIRS = name "Heirs to skull crag", start module **5**, entry 1, `GEO005.DAT` exists and is
  19x19 (bytes 26/27), module name at 142 "TOWN AT BEGIN". **TUTORIAL.DSN has start module 1 but
  contains only `GEO040.DAT`**, so "GAME001 names the start module unambiguously" is false for it:
  `start_route` in `tools/frua_events.py` itself raises `start module N has no GEO file`. T11's
  stated risk (explicit module number fallback) is real and already triggered by a shipped design.
- Map header fields (`hackdocs_extracted/GEODATA.TXT`): height 26, width 27, wall slots 28-30,
  entry col/row/facing at 38.. in 4-byte records.
- Event semantics (`docs/engine/research/frua-event-format.md`, `tools/frua_events.py`) are out of
  scope; the preview is map only.

### What a read-only preview needs
1. Pick a design directory: all 26 GBBOOT switch letters are used, so use a **positional token**
   (e.g. `GBBOOT /E HEIRS.DSN`) or auto-discover a single `*.DSN` directory with DOS find-first;
   unverified which `gbboot.asm` arg loop tolerates a non-switch token (it parses `/x` forms).
2. Read `GAME001.DAT` byte 48 (and optionally 49) from that directory (`size == 388` check).
3. Format `GEOnnn.DAT` (3 decimal digits), `file_exists`; if missing, fail closed with a
   distinct message (TUTORIAL.DSN case) or accept an explicit module override via the existing
   `/B n` (`entry_override_num`).
4. Compose the path into a buffer (the profile paths are static strings), set `geop`,
   `mapid = 0`, and run the existing `build_geo_tail` / `child_geo` (`CCGEO /B file 0 out`), then
   the normal `CCFP /W` or `/S` tail. Skip ECL: no `SCRIPT.GLB`, no events, no `eclp`.
5. Without a design token, `.missing` fail-closed behaviour must be byte-identical to today.
6. Wall art: no DAX `8X8D`/`WALLDEF` exists for a DSN; the WGRD bridge presumably renders with the
   untextured path. **Not verified**; the first DOSBox run decides what the preview looks like.
