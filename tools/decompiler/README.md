# Greybox Decompiler Import Helpers

These scripts consume packages generated by:

```powershell
python tools/export_decompiler_inputs.py --strict
```

Each `build/decompiler-inputs/<package>/` directory contains a path-independent `manifest.json`
and CSV tables. Source files are located by filename and SHA-256 under a supplied game directory.
The scripts refuse missing or changed retail bytes.

## Address Model

Use a 16-bit x86 protected-mode analysis database. The manifest maps the resident image at a
synthetic address and each mutually exclusive overlay into a separate 64 KiB slot. These addresses
exist only to make all code visible in one database. Runtime selectors and RTLink segments are
metadata, not aliases for synthetic addresses.

Only statically resolved routed calls become references. Unresolved VROOMM selectors, out-of-range
stub targets, approximate RTLink boundaries, and MZ load relocations remain labelled evidence.

## Ghidra

1. Create a new program using language `x86:LE:16:Protected Mode`. A raw bootstrap import at address
   zero is sufficient; generated blocks begin at `0x00100000`.
2. Add `tools/decompiler` to Script Manager's script directories.
3. Run `ghidra_import.py` with exactly two script arguments: the package's `manifest.json` and the
   game directory containing the retail binaries.
4. Run auto-analysis after the script finishes.

The importer verifies hashes, creates the resident/overlay blocks, imports same-game symbols, adds
only resolved call references, defines the provenance-scoped signature seed functions, and marks the
original MZ entry point. IDA's signature command can then generate `.pat`/`.sig` files from eligible
`gbx_*` and `coab_*` function names.

`candidate_symbols` are imported separately with a `candidate_*` name and a plate/repeatable comment
containing their unresolved runtime claim. They never enter `symbols.csv` or supply semantic names to
signature seeds. Promote one only after the title-local runtime gate named in its claim boundary.

## IDA

1. Create a new 16-bit x86 database from a raw bootstrap byte.
2. Run `tools/decompiler/ida_import.py` with the manifest and game directory as its two script
   arguments. In batch mode these follow the script path in IDA's `-S` argument.
3. Wait for the importer-triggered analysis to complete, then save the database.

**Ghidra**: verified 2026-07-17 with a real headless smoke import (Ghidra 12.1.2, CoAB manifest,
genuine GOG retail bytes) — clean import of 37 blocks, 1980 resolved calls, 851 symbols. Ghidra
12.1.2 defaults `.py` GhidraScripts to the `PyGhidraScriptProvider` (real CPython+jep, not present
here); `ghidra_import.py` carries a `# @runtime Jython` header to select the bundled Jython
provider instead — install the Jython extension from the main Ghidra zip's
`Extensions/Ghidra/ghidra_<version>_Jython.zip` into `Ghidra/Extensions/Jython/` if it is not
already present.

## Ghidra FID (Function ID) database

`ghidra_fid_build.py` compiles a real, queryable Ghidra `.fidb` from the current program's
functions — run it as a *second* `-postScript` in the same headless invocation, right after
`ghidra_import.py` has populated the seed functions:

```
analyzeHeadless <project> <name> -import <bootstrap> -loader BinaryLoader -loader-baseAddr 0 \
  -processor "x86:LE:16:Protected Mode" -cspec default \
  -scriptPath tools/decompiler \
  -postScript ghidra_import.py <manifest.json> <game-directory> \
  -postScript ghidra_fid_build.py <fidb-path> <library-family> <library-version> <library-variant>
```

It calls `FidService.createNewLibraryFromPrograms` (the same API the GUI "Function ID ->
Create/Populate FidDb" actions use) against `currentProgram.getDomainFile()`, so it must run in
the same session/program that `ghidra_import.py` just populated. Verified 2026-07-17 against the
CoAB manifest's 196 signature seeds: `196 attempted, 196 added, 0 excluded`, and the resulting
`.fidb` was independently re-opened and queried in a **separate** headless session (no shared
state with the writer run), confirming 1 library and 196 function records with the expected
`coab_*` names. Two Windows-specific gotchas: `-processor "…:default"` combined with the compiler
spec in one string throws `Unsupported language` — pass `-cspec default` separately; and
`analyzeHeadless.bat`'s own argument-parsing loop breaks on any path containing unescaped
parentheses (e.g. `C:\Program Files (x86)\...`) regardless of quoting — resolve the 8.3 short path
(`Scripting.FileSystemObject` in PowerShell, or `dir /x`) and use that instead.

**IDA**: not installed. IDA is Hex-Rays-licensed commercial software — it must come from the
user's own valid license/download, never an unofficial source. Its smoke-import gate remains
environment-pending until then; Python syntax, manifest integrity, source hashes, block ranges,
target references, signature eligibility/masks, and CSV row parity are covered locally.

Source-directory notes: CoK/DoK/DQK use this repo's own top-level game folders (no path
gotchas). All eight remaining GOG-sourced titles came from this machine's existing GOG Galaxy
install (`C:\Program Files (x86)\GOG Galaxy\Games\<Title>\`) — resolve the 8.3 short path first

`analyzeHeadless.bat`'s own argument parser regardless of quoting, per the gotcha above.
Neverwinter Nights (DOS/AOL) is not in GOG Galaxy on this machine; its retail `GAME.EXE`/`GAME.OVR`
were found and hash-verified at `D:\Games\Neverwinter Nights DOS\neverwinter-nights\neverwint\`.

One real bug was found and fixed in `ghidra_import.py` during this sweep: FRUA's manifest
contains a genuine zero-length RTLink overlay descriptor block (`ovr020` — an empty/unused
overlay slot; `boundary_evidence: "unresolved-code-boundary-whole-blob"`,
`prefix_source: "unknown"`, `size: 0`). Ghidra's `Memory.createInitializedBlock` throws
`IllegalArgumentException: Block must have a non-zero length` on any zero-size block, so the
importer now skips creating memory for `size == 0` block rows (still recording them in its
in-script bookkeeping dict) instead of calling into `Memory` for them. Confirmed first that no
call, symbol, or signature-seed row in any of the 11 manifests targets a zero-size block's
synthetic address, and that FRUA is the only package with a zero-size block, before landing the
fix — it re-verified clean (116/116/0) afterward.

Practical mechanics for reproducing any of the above: each package needs its own `project/` and
`verify-project/` directory created **before** invoking `analyzeHeadless.bat` (it errors with
"Directory not found" if the project path doesn't already exist, unlike the sample project dirs
that ship pre-created). Also invoke the driver `.bat` with stdin redirected from a closed handle
(e.g. `cmd /c script.bat < NUL`, or `< /dev/null` from Git Bash) — on any `HeadlessAnalyzer`
error path the launcher's `pause` step hangs forever waiting for a keypress that will never
arrive in an unattended/headless run.
